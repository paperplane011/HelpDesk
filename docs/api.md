# Контракт API

Базовый URL локально: `http://localhost:5080`. Интерактивное описание: `/swagger`; OpenAPI: `/swagger/v1/swagger.json`. JSON использует camelCase и строковые enum. Даты возвращаются в UTC с суффиксом `Z`. Аутентификация для всех маршрутов заявок: `Authorization: Bearer <accessToken>`.

## Модель заявки

| Поле | Значение |
| --- | --- |
| id | GUID, создаётся сервером |
| title | Обязательное, после trim 1-200 символов |
| description | Обязательное, после trim 1-10000 символов |
| priority | Low / Normal / High / Critical; при создании по умолчанию Normal |
| status | Open / InProgress / Closed; меняется только командами |
| ownerId | Identity ID из токена, нельзя задать в теле |
| assigneeId | ID взявшего заявку сотрудника или null |
| createdAt | UTC, неизменяемая дата создания |
| updatedAt | UTC, обновляется в том числе при комментарии |
| closedAt | UTC при закрытии, null в активной заявке |
| version | Новый GUID после каждого изменения |

`PUT` редактирует только title, description, priority. Остальные поля нельзя менять прямой отправкой JSON: они не входят во входной DTO. Передавайте `version` в `PUT`, `take`, `close`, `reopen`, `comments POST`. Пустая, отсутствующая или устаревшая версия даёт `409`. После каждого успеха берите версию из ответа. POST комментария возвращает **обновлённую заявку**, а не комментарий: это даёт клиенту новую версию. Комментарии доступны через GET.

## Список

`GET /api/tickets?status=Open&priority=High&sortBy=Priority&descending=true&page=1&pageSize=20`

Все параметры необязательны. Фильтры пересекаются через AND. SortBy: CreatedAt (по умолчанию), UpdatedAt, Priority. Descending по умолчанию true. Page 1..1000000, pageSize 1..100. Неверные значения - `400`. При совпадающем ключе используется Id по возрастанию. Приоритет сортируется Low < Normal < High < Critical. Возвращается `{items,totalCount,page,pageSize,totalPages}`. При отсутствии данных items=[], totalCount=0, totalPages=0; далёкая страница тоже даёт пустой items, но сохраняет общий count.

Комментарии: `GET /api/tickets/{id}/comments?page=1&pageSize=20`. Сортировка от старых к новым, затем Id. Тело комментария обязательно, 1..4000 символов после trim. Закрытая заявка не принимает комментарии.

## Права и состояния

| Операция | Владелец | Другой пользователь | Support |
| --- | --- | --- | --- |
| Создать | Да, себе | Да, себе | Да, себе |
| Читать / список / комментарии | Свои | Чужие скрыты, 404 | Все |
| Редактировать / комментировать | Свои активные | 404 | Любые активные |
| Take | 403 | 403 | Только Open, назначает на себя |
| Close | 403 | 403 | Только свой InProgress |
| Reopen | Свои Closed | 404 | Любые Closed |

Переходы: Open -> InProgress (take) -> Closed (close) -> Open (reopen). Неподходящее состояние - `409`. Повторное открытие очищает assigneeId и closedAt. Повторный take невозможен, переназначение не реализовано. Сотрудник может редактировать активную заявку коллеги, но закрывать может только свою. Это осознанное правило небольшой команды поддержки.

## Ошибки

| Код | Причина и действие клиента |
| --- | --- |
| 400 | Неправильный JSON, пустое/длинное поле, недопустимый enum или параметры. Исправить запрос |
| 401 | Нет токена, неверный токен/пароль или блокировка входа. Войти заново / обновить токен |
| 403 | Требуется роль Support. Не повторять с теми же правами |
| 404 | Нет доступной заявки. Одинаковый ответ для отсутствующей и чужой |
| 409 | Версия устарела либо нарушено правило статуса. Получить актуальную заявку и проверить detail |
| 429 | Более 30 запросов к группе Identity за минуту с одного IP. Подождать |
| 500 | Неожиданная ошибка. Сохранить traceId; детали доступны в логах сервера |
| 503 | /health/ready не смог прочитать таблицу заявок |

Пример ошибки бизнес-правила (значения instance/traceId зависят от запроса):

```json
{
  "title": "Business rule violation",
  "status": 409,
  "detail": "Reopen the closed ticket before editing or commenting.",
  "instance": "/api/tickets/00000000-0000-0000-0000-000000000001",
  "traceId": "request-specific-id"
}
```

Стандартные Problem Details могут также включать `type`. Ошибки валидации дополнительно содержат словарь `errors`. Некоторые стандартные ошибки Identity имеют собственные title/detail/коды полей: это встроенный контракт Identity. Тексты ошибок на английском для совместимости с API-инструментами; руководство объясняет их по-русски.

## Identity

Основные маршруты: POST register, login, refresh под `/api/auth`. Register принимает email/password. Пароль от 12 символов, с верхним и нижним регистром, цифрой и спецсимволом. Повторный email запрещён. 5 неудачных входов блокируют учётную запись на 5 минут.

Login с `useCookies=false` выдаёт tokenType, accessToken, expiresIn, refreshToken. `expiresIn` равен 1800 секундам. Refresh обновляет пару токенов; refresh не одноразовый (защита от повторного использования не добавлена). Cookies также предусмотрены встроенным Identity, но документированный и тестируемый сценарий проекта использует bearer. Не передавайте токены в URL.

`MapIdentityApi` также создаёт manage/info, manage/2fa, confirmEmail, resendConfirmationEmail, forgotPassword и resetPassword. Настоящий email-провайдер не подключён. Сценарии доставки писем в этом проекте не реализованы. Привилегии назначаются консолью или демо-seed, регистрация роль не принимает.
